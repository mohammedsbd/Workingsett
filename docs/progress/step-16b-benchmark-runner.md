# Step 16b: Benchmark runner, baselines and metrics

## Goal

Build a benchmark that answers the first question buyers ask: "why not just truncate old messages, or summarize everything?" It compares Parsim against naive baselines, on the demo agents from 16a, with honest metrics and generated reports.

## What was built

All of it is in `demo-agent/`.

- **Runner** (`npm run bench -- --agent research|support --runs 3 --provider <name> --model <model> [--arms all|<list>] [--dry-run]`). Every task runs in five arms, with tools replaying recordings and temperature 0:

  | Arm | What it is |
  | --- | --- |
  | `full` | No Parsim, full context |
  | `truncate` | Naive truncation: system prompt, first user goal and the last N turns (client side) |
  | `summarize` | Naive summarization: one internal-model summary of everything older than N turns, refreshed every M turns (client side) |
  | `parsim-shadow` | Through Parsim, project in shadow mode |
  | `parsim-on` | Through Parsim, project in on mode |

  - N = M = 6 (`BENCH_TRUNCATE_TURNS`, `BENCH_SUMMARY_EVERY`), the same as Parsim's protected turns (your choice).
  - The runner signs in to Parsim, creates or reuses one project per Parsim arm with the right GC mode through the existing API, and makes a key for the run.
  - Extra options: `--tasks <n>` (the first n tasks), `--judge`, `--budget <usd>`, `--resume`, `--yes`, `--max-steps`.
- **Metrics per task and arm:**
  - Task success: exact checks from the side-effect log decide it (your choice). `--judge` adds the internal model's checklist verdict. Mean and standard deviation across runs.
  - Input, output and cached input tokens.
  - Cost three ways:
    - raw;
    - net: what went upstream (Parsim's own count when larger, which includes recall follow-ups the agent never sees), plus the summarize baseline's summaries, plus Parsim's compression cost;
    - cache-adjusted, with cached input at the cached input price.
  - Proxy latency overhead at p50 and p95 against the full arm. Rate-limit waits are recorded apart (see Decisions).
  - Recalls per task, and recall success: whether the recalled original held a fact the task needed, read from Parsim's session detail.
  - Side-effect safety: each arm's side-effect calls against the full arm's, flagging missing, duplicated, changed (status or answer) and extra calls.
  - Wall time, and everything broken down by task type (normal, late_recall, cross_ticket).
- **Significance:** a difference counts as significant only when it is larger than the run-to-run spread (the larger standard deviation of the two arms). With one run the report says "single run".
- **Budget guard:**
  - Before a real run, the bench prints estimated requests, tokens and cost per arm and in total, then asks for confirmation. `--yes` is accepted only for free-tier providers.
  - `--budget` stops cleanly once spending (at list price) passes it, writing partial results.
  - For free tiers it also says whether the run fits the daily quota (`<PROVIDER>_DAILY_TOKENS`, `<PROVIDER>_DAILY_REQUESTS`) and roughly how many days it needs.
- **Resume:** progress is saved after every task (`runs/bench/<id>/progress.json`, gitignored, since it holds the run's Parsim keys). `--resume` continues the newest unfinished bench of that agent, provider and model, with the agent's conversation, side effects and the Parsim session restored. Finished tasks are not repeated.
- **Report** (`docs/benchmarks/<date>-<agent>-<provider>-<model>.md`), generated by code with a `.json` of all raw numbers and an `.svg` chart (task success against net cost). It contains:
  - the headline: "Parsim on: X% lower net cost, success Y% vs Z% for full context. Truncation: A% lower net cost, success B%." (it says "higher" when an arm costs more);
  - per-arm tables, success by task type, latency, recalls, side-effect safety, the exact command, the model, the Parsim version and git commit, the run dates, and the method;
  - a "Development run, not for publishing" banner on free-tier runs.

  `npm run bench:report -- --id <bench>` renders a report again from saved results, so layout changes never mean hand edits.
- **Dry run** (`--dry-run`): a scripted fake upstream (`src/bench/fake-upstream.ts`, OpenAI format) plays a deterministic agent that knows only what is in each request. Truncation and summarization therefore lose facts as with a real model, and through Parsim the agent recalls archived pages with `parsim_recall`, choosing the stub that answered the page fetch it needs.
- **Fixes found on the real run:**
  - Groq rejects malformed tool calls with a 400 (`tool_use_failed`). The OpenAI-format client now asks again, up to twice, at a small temperature (0.3).
  - Step latency now excludes rate-limit waits.
- **Price table:** Groq `openai/gpt-oss-120b` at its list price ($0.15 input, $0.075 cached, $0.60 output per 1M tokens), so free-tier runs can be compared.

  - the significance flag;
  - side-effect diffs (missing, duplicated, changed arguments, extra; reply wording ignored);

  - the budget estimator and abort, and the daily quota estimate;
  - `--resume` skipping finished tasks (a run stopped by a daily quota after two tickets resumes with only the last two);
  - report generation (snapshot tests of the markdown, JSON and SVG from a fixed result set), the dev-run banner, the "higher" wording and recorded waits;
  - judge parsing, and the retry of malformed tool calls.
- **Backend e2e** (`test/bench/bench-dry-run.e2e-spec.ts`): the bench CLI runs both agents over all five arms against the scripted upstream, with Parsim booted in-process behind it.
  - Support: full and parsim-shadow pass every ticket, truncation loses cross-ticket details, and each Parsim arm is one Parsim session.
  - Research: late-recall answers pass with full context, fail with truncation, and pass in parsim-on through real `parsim_recall` calls.

## Development benchmark (Groq free tier)

`npm run bench -- --agent support --runs 1 --provider groq --tasks 4 --yes`, then `--resume`. Report: [2026-10-17-support-groq-openai-gpt-oss-120b.md](../benchmarks/2026-10-17-support-groq-openai-gpt-oss-120b.md).

**Headline (as generated):** "Parsim on: 0.5% higher net cost, success 100.0% vs 100.0% for full context. Truncation: 3.2% lower net cost, success 100.0%."

| Arm | Success | Input tokens | Net cost (list price) | vs full |
| --- | --- | --- | --- | --- |
| full | 100% | 25,696 | $0.00471 | - |
| truncate | 100% | 20,419 | $0.00456 | 3.2% lower |
| summarize | 100% | 21,319 | $0.00485 | 3.0% higher |
| parsim-shadow | 100% | 25,962 | $0.00526 | 11.7% higher |
| parsim-on | 100% | 25,074 | $0.00473 | 0.5% higher |

Side-effect safety: no missing, duplicated or changed actions in any arm (summarize made one extra call).

**What it shows, honestly:**
- The benchmark works end to end on a real model across all five arms, including real requests through Parsim, Parsim's own session records, costs, the side-effect comparison and the report.
- It does not measure savings: four tickets stay below Parsim's 8,000-token minimum context, so the GC made no decisions, and the cost differences are run-to-run variation in output tokens.
- Tickets 1 to 4 contain no cross_ticket case, so no memory difference could show either.
- The first attempt stopped at the truncate arm when Groq rejected a malformed tool call (fixed, then resumed with `--resume`). That made the run a real test of resume: it skipped the finished arm and continued the truncate arm at ticket 2.
- The latency in this report includes Groq's per-minute rate-limit waits, which were not yet recorded apart, and the report says so. Later runs record them separately.
- The run cost $0 (free tier); about $0.024 at list price.

## Decisions and trade-offs

- **4 tickets, not the agreed 10** (your choice after I raised it): every free Groq model on your key is limited to 8,000 tokens per minute (checked from the response headers). A larger request is refused outright, and full-context support passes that around ticket 5. Ten tickets would also need about 1.07M tokens, about six days of the free daily quota.
- **List prices for free-tier runs**, with a banner, so arms can be compared.
- **Exact checks decide success; the judge is opt-in**, for repeatable results and less quota.
- **N = M = 6**, matching Parsim's protected turns, so the baselines get the same recent context Parsim keeps.
- **Net cost takes Parsim's upstream count when it is larger**, because recall follow-ups happen inside Parsim and the agent only sees the final response's usage.
- **The scripted fake is a "careful agent"**: it uses only what is in the request, so dry runs show the real mechanics (truncation forgets, Parsim recalls) without a model.
- **Retries of malformed tool calls use temperature 0.3**: at temperature 0 the model tends to repeat the same malformed call. Only those retries deviate from temperature 0.

## Known issues and next steps

- **No real-model savings or memory numbers yet:** the free tier cannot run long enough contexts. 16c runs both agents, three runs and all arms on Gemini Flash with a paid key, which is where the headline numbers come from.
- **Groq's free tier stays limited to short runs** (about 4 support tickets with full context). Groq's paid Developer tier would allow full runs for cents.
- **Compression is off in the bench by default** (`BENCH_PARSIM_COMPRESSION`). Turning it on needs the backend's internal model configured.
- **The size estimate is rough:** it assumes average tool results and treats parsim-on like full context (an upper bound).
